## W8′-fix correction (orchestrator live verification, 2026-07-03)
The orchestrator ran `agy -p` live for the first time this round and found the argv shape AND the
success/error mapping wrong. Both `src/lib.rs` and `docs/specs/adapter-antigravity.md` were amended
in place (spec-sanctioned reality correction, not a silent code fix):
1. **Hidden flag required.** Plain `-p <prompt>` emits plain TEXT, not JSON. `--output-format json`
   (absent from `--help`, present in binary strings) is REQUIRED — VERIFIED live twice.
2. **`-p`'s prompt is a flag VALUE, not a free positional.** `-p` consumes the single argv token
   immediately following it. `agy -p --model X ...` was VERIFIED live to hand the agent `"--model X
   ..."` as its prompt. Corrected argv places `-p "<prompt>"` as the strictly-last two elements:
   `agy --output-format json [--conversation <cid>] --model <m> --sandbox
   --dangerously-skip-permissions -p "<prompt>"`.
3. **Success mapping corrected.** VERIFIED live: `status:"SUCCESS"` occurs, AND a good, on-topic
   `response` can occur alongside `status:"ERROR"` + a populated `error` (tool-denial decoration — the
   model narrating a denied tool call inside an otherwise-useful reply). So `status`/`error` no longer
   gate success. **New mapping: success iff `conversation_id` and `response` are BOTH non-empty
   strings; otherwise `Err("agy turn failed: {raw line}")`** (status/error still ride along inside the
   raw line, decorating the message, not deciding the branch).
