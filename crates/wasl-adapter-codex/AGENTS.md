Two design choices in `parse_reply` were needed to reach genuine 100% given the frozen fixtures (none of which exercise a second `thread.started` line or an `item.completed` missing its `item` field): (1) `thread_id = thread_id.or(event.thread_id)` instead of an `if thread_id.is_none() { .. }` block, so "first occurrence wins" costs no branch region; (2) the `item` field is typed `serde_json::Value` (default `Null`) rather than a nested `Option<Item>` struct, so a missing/absent `item` flows through the same `.get("type"))` lookup as a present-but-wrong-kind item instead of forking into a distinct "item present vs. absent" branch. Both are semantically identical to the more naive formulations — no dead code, no `#[allow]`-for-coverage, no panics. The single named error helper `ad` is passed bare to `map_err` at the `ProcessCliInvoker` IO sites (stdin write, `wait`), same technique as E3. (The `[lints.clippy]` allow-table only silences two pure-STYLE lints tripped by the frozen tests — `type_complexity`, `default_constructed_unit_structs`; `src/**` has neither pattern.)
