**Spec:** `../../docs/specs/adapter-opencode.md` (VERIFIED against the real `opencode` CLI — opencode 1.18.4, 2026-07-20; see the spec's CONTRACT STATUS table for the per-row live evidence).

- Deps: `wasl-adapter`, `serde`, `serde_json`, `async-trait`, `tokio` (process, io-util). NO `uuid` dep — opencode mints its own session ids (a `ses_`-prefixed id reported as the top-level `sessionID` on every JSONL event); the adapter never fabricates or validates one beyond passing it through the ledger. Tests use a fake `CliInvoker` + stand-in commands (`cat`, `sh -c`) — NO real `opencode`, NO network, in the default suite.
- Tests before code, read-only to code-agent. No `#[ignore]`/stub/tautology. Every test asserts a concrete value; tests compile only against the public API + `wasl_adapter` public types.
- **Contract implemented (per spec):** `compose_prompt` is byte-identical to `wasl-adapter-claude`/`-codex`'s composition. `build_argv` emits `[bin, "run", "--format", "json", ("-m", model)?, prompt]` for `Turn::First` and `[bin, "run", "--format", "json", "-s", sid, ("-m", model)?, prompt]` for `Turn::Continuation` — the prompt is ALWAYS the strictly-LAST (trailing positional) argv element, and `-m` is accepted on BOTH turns (verified — unlike codex, which drops `--sandbox` on resume). `parse_reply` walks the JSONL stream: blank/whitespace-only lines skipped; each non-blank line must parse as a JSON object else `Err("parse opencode output line: {e}")`; the top-level `"sessionID"` is recorded (first occurrence wins); `type=="error"` -> `Err("opencode error: {name}: {message}")` from `.error.name`/`.error.data.message` (falling back to the raw line if those fields are absent — no invented shapes); `type=="text"` -> collect `(.part.messageID, .part.time.start, .part.text)`; anything else (`step_start`, `step_finish`, unknown future types) ignored. Reply text = the text parts of the LAST messageID seen (final assistant message), ordered by `.part.time.start`, concatenated. End: no sessionID -> `Err("opencode output had no sessionID")`; no text parts -> `Err("opencode output had no assistant text")`. `OpencodeAdapter` keeps an in-memory `Mutex<HashMap<String, String>>` context_id -> session_id ledger, written ONLY on full success (invoker Ok AND parse Ok). **MATCHED single fresh-`First` retry (like claude, unlike codex's blind retry):** a `Continuation` invoker error whose message CONTAINS `Session not found` (the verified stale-session stderr, wrapped by the invoker as `"{prog} {status}: {stderr}"`) triggers exactly ONE fresh-`First` retry (re-learn on success, propagate on failure); a `Continuation` error WITHOUT that substring propagates unchanged (environmental, not a stale session); a `First` invoker error propagates with no retry; the retry is never retried. Any parse error (incl. a `type=="error"` stream, or no assistant text) propagates WITHOUT retry and WITHOUT touching the ledger. **M2 EPIPE fix:** `ProcessCliInvoker`'s stdin write swallows `BrokenPipe`/`WriteZero` as benign (opencode never reads stdin — prompt is positional — so it can close its stdin end before the empty write completes), proceeds to `wait_with_output`, and keeps every other write error fatal (copied from the `wasl-adapter-claude` write-path pattern). **Empty stdin:** `deliver` always calls `invoke(argv, "")` — opencode's prompt rides in argv (a trailing positional), never on stdin.

  - **UNGUARDED edge (documented, not fixed here — a future W-block):** a pathological error class (verified: context overflow with autocompact) makes `opencode run` LOOP indefinitely and never self-terminate. W9 does NOT add an in-invoker JSONL-streaming watchdog — the `(argv, stdin) -> stdout` seam stays identical to the siblings; a hung child is bounded at the node's A2A RECEIVE/task-timeout layer, not inside `ProcessCliInvoker`. The deployment mitigation (`OPENCODE_DISABLE_AUTOCOMPACT=1` + an adequately-large-context model) turns the loop into a single `type=="error"` event that `parse_reply` maps to a clean `AdapterError` and a normally-exiting process. This is an honestly-unguarded edge in the default suite.
